# Stage 3：图标、快捷方式与手动恢复

本页是发布准备阶段的 Stage 3，与早期美术 brief 的 Stage 3 编号不同。

## 使用

- 右键角色 → 隐藏桌宠：两位角色同时隐藏，屏幕右侧显示白兔 `hiding_icon.png`。
- 右键白兔 → 显示桌宠：恢复两位角色，保留原暂停状态和大小；白兔消失。
- 右键白兔 → 退出桌宠：关闭整个程序。
- 没有分钟选项、自动恢复倒计时。隐藏不保存到下次启动。白兔初始位于主屏右侧，可左键拖动，在本次运行中记住位置；不是系统托盘图标。
- 原图保留在 assets/characters/icon/，不修改内容。icon.png 用于程序图标，hiding_icon.png 用于隐藏恢复入口。

## 快捷方式

- Windows：完整解压到准备长期保留的文件夹，运行 create-shortcut.cmd，在桌面生成带图标的快捷方式。此步骤不安装系统服务，不需要管理员权限。更新或移动文件夹后重新运行，以更新目标路径。删除快捷方式不会删除程序。
- Linux：完整解压后执行 `python3 create-shortcut.py`，创建桌面及应用菜单入口。GNOME 若提示，右键桌面快捷方式选择「允许启动」。移动文件夹后重建入口。
- macOS：实验 .app 自带图标；可用 Finder「制作替身」并放到桌面。无 macOS 实机，不声明已验证；应用仍未 notarize。
- 仍为便携包，没有安装程序，也不自动改动用户的桌面；仅显式运行上述快捷方式助手时创建入口。

## 检查

1. EXE／.app／Linux 入口使用两只兔子的应用图标。
2. Windows 桌面快捷方式可以启动整个程序，资源和设置读取正常；关闭应用再测试快捷方式，避免同时运行两个副本。
3. 从待机、对视、拥抱中隐藏，只有白兔可见；两位角色、拥抱及旧菜单没有残留点击区域。
4. 白兔周围透明区域允许操作后方窗口，不抢输入焦点；右键菜单在屏幕内。
5. 「显示桌宠」恢复双方；暂停时隐藏后再恢复，仍保持暂停。
6. 100%／150%／200% 大小下重复隐藏／恢复；在恢复后再次打开菜单，拖拽、互动、退出均正常。
7. 隐藏时改变主屏可用区域／休眠恢复，白兔仍位于有效区域内；此项需要实机测试。
8. 右键白兔选择退出，所有窗口和进程退出。

构建：`python3 tools/build_stage1.py --stage 3 --platform all`。不发布新 Release，不改版本号。

图标导出依据：[Godot 4.6 Windows 图标文档](https://docs.godotengine.org/en/4.6/tutorials/export/changing_application_icon_for_windows.html)。

## 互动与指南补充

- 对视、拥抱各自冷却 30 秒；任意动作结束／取消后有 5 秒共同间隔。自动与手动采用相同规则；失败且未开始的请求不产生冷却。
- 暂停、打开菜单、隐藏期间继续计时；不把另一个动作的冷却重置。测试：手动拥抱结束，5 秒后可对视（位置合适且对视没有自己的冷却），拥抱仍需等待自己的剩余时间。
- 打开包内 START_HERE.html：离线图标、导航、平台启动步骤、隐藏／恢复及互动规则应完整；README.txt 为文字入口。网页不加载外部字体／脚本或网络资源。

9. 左键拖动白兔到四个边缘和角落，检查图标及右键菜单均在屏幕内；拖动不恢复角色。显示角色后再次隐藏，白兔保留本次运行中的位置。

10. 右键角色 → 帮助 → 使用指南（离线），应使用系统默认 HTML 打开方式打开包内 START_HERE.html；无需联网。关闭网页不影响桌宠。包缺失指南时，按钮提示完整解压；未配置 HTML 打开方式时提示直接打开文件。macOS 请保留整套解压目录，指南在 .app 同级。
